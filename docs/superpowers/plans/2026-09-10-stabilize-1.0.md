# Stabilization toward 1.0

Baseline: `1cbc7817b0d08d6d20414b7d266cfc41a803ed7e` (0.1.0).
Work branch: `codex/stabilize-1.0`. The existing desktop, visual language,
package providers and machine safety boundaries remain the design constraints.
This pass fixes reproducible defects; it does not certify untested hardware or
publish a 1.0 release merely by changing a version string.

## Runtime

- In `render/src`, cover corrupt assets, clipped surfaces, resize and keyboard
  handling with focused regression tests. Fix atlas/RCEL validation, per-row
  clipping, bar buffer recreation, column PTY/VT geometry and modifier handling.
- Give the lock screen one bounded redraw scheduler. Preserve the compositor's
  session-lock handshake and fail-closed behavior.
- Correct hero cache invalidation and session/process ownership in
  `bin/null-hero`, `bin/null-wallpaper` and `bin/null-lock`.
- Run `cargo test --locked --all-targets`, production release compilation and
  headless Wayland checks where the environment supports them.

## Bake and clean builds

- Add numerical regression tests for half-float subnormals and temperature
  reduction in `bake/` and `render/src/derive.rs`.
- Repair dependency ordering and output paths in `bin/null-prebake` and
  `bin/null-build`, including placeholder and icon generation.
- Verify the released HDR master's checksum before restoring it. Exercise a
  clean prebake and compare CPU/Rust derivation, rather than trusting assets
  left over from an earlier build.

## Installation and packaging

- Mock external commands to prove the last-administrator guard applies to all
  arguments in `bin/null-users`.
- Ensure `bin/null-machine-sync` records success only after required writes
  succeed and reruns after package upgrades.
- Encode installer answers safely for Kickstart, testing quotes and backslashes.
- Validate required prebuilts and publish only the current package build in
  `bin/null-package`; make dirty-tree source selection explicit and accurate.
- Build and inspect the resulting RPM. Run destructive integration checks only
  inside a newly created disposable guest, never on the workstation.

## Desktop controls and repository maintenance

- Test application resolution using temporary XDG directories and recording
  executables. Preserve quoted arguments, field-code placement and user desktop
  overrides in `bin/null-defaults`, `bin/null-open` and `bin/null-run`.
- Validate input settings before writing, remove duplicate writers and surface
  failures in settings instead of displaying false success.
- Add a documented source-only check entry point and CI, distinct from the
  installed-system and hardware checks. Keep tests deterministic and avoid
  installing or reconfiguring the test host.
- Remove duplicate ignore rules and correct stale build/status documentation.

## Acceptance and evidence

For behavioral fixes, record a failing reproduction before the change and a
passing regression afterward. Run the source suite, Rust tests and release
build, clean prebake and RPM build. Review the final diff for regressions and
unnecessary changes. Record commands, counts and unresolved failures in a
review report with clear distinctions between source tests, built artifacts,
guest behavior and historical evidence.

Release 1.0 still requires the criteria in `docs/goals.md`: a cold ISO install
on real hardware, its device/suspend/dock checks and mail/office visual
acceptance. Those gates cannot be inferred from source or WSL results.

## Live media acceptance (user clarification, 11 September)

The main media must support trying the desktop and installing it. Extend the
existing live-image path with a Try / Install welcome and a discoverable
installer application. Use Fedora's supported graphical liveinst path; keep
Kickstart automation on the separate installer image. Prove the live desktop
boots without an installed OS, Try does not launch an installer, and graphical
installation reaches an installed desktop without the live account, autologin,
passwordless sudo, debugging keys or other live-only state. Check the no-password
live session cannot become stuck behind a password lock. Test both firmware
boot paths in disposable VMs and retain exact image/package provenance.
