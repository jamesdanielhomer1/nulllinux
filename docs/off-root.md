# Moving the session off root

> **Superseded by [system-wide.md](system-wide.md).** This describes moving
> the desktop into one account, which was the wrong shape: it works for one
> person and a second account has to copy it. The checkout now lives in
> `/opt/nulllinux` and is installed system-wide. What is still true here is the
> reasoning about PipeWire, the install location being named once, and the GTK
> links that no script had ever made.

Requested so audio works. PipeWire **refuses to run as root** — a deliberate
upstream choice — so every audio reading on this desktop was `--`, the volume
keys did nothing, and the audio component could not be exercised at all.

## What made this harder than it should have been

**The install location was written out thirty-three times.** Across
`config/sway/*` alone, plus three Rust fallbacks and a shell default. Moving
the checkout therefore meant thirty-three edits, any one of which could be
missed *silently* — sway does not complain about an `exec` pointing at nothing,
it simply does nothing when the key is pressed.

Two fixes, so this is a one-line change next time:

- **`set $null` names it once** in the sway configuration, and everything else
  refers to `$null`.
- **The binaries and the shell profile derive their own root** from their own
  location rather than carrying a literal. `/root/nulllinux` baked into a binary is
  an install location baked into a binary.

`idle.conf` is deliberately *not* in that scheme: it is read by swayidle, not
by sway, so a sway variable there would be passed through to a shell that has
never heard of it. It is generated by `bin/null-idle`, which writes real paths.

**The GTK links had never been made by any script.** They existed because I
created them by hand during an earlier phase, so they were present on the
machine that built the system and would have existed nowhere else. `null-link`
now discovers every configuration directory the repository owns, and names the
four *exclusions* with reasons instead of listing the inclusions.

## What was done

- The checkout was **copied**, not moved, to `/home/james/nullLinux`, and the HDR
  master with it. `/root/nulllinux` is left intact as a working fallback until the
  new session is confirmed.
- `set $null` in the copy points at the copy.
- `bin/null-link` was run **as james**, so the very first login already has the
  right configuration rather than Fedora's default sway. Verified: every file
  the session needs is readable by james, the configuration validates, and the
  binding audit passes on it — 74 bindings, none doubled.
- `bin/null-firstrun` does the rest, and **refuses to run as root or without a
  session bus.** That restriction is the point: the settings keys that outrank
  configuration files (§8.10), the icon cache and the browser profile all live
  in a per-user database, and writing them from another account puts them
  somewhere invisible and wrong at the same time.

## Audio was proven, not assumed

With a temporary lingering session:

```
PipeWire 'pipewire-0' [1.6.8, james@nox, cookie:2307571785]
```

The daemon **runs** for james, which is exactly what it will not do for root.
Its device list was empty because sound devices are ACL'd to whoever holds the
seat, and root still held `seat0`; they attach when james logs in there.

Lingering was enabled only for that measurement and put back to `no`.

## What remains, and it needs a person

1. Log out of the root session — `super+escape`, then **logout**.
2. Log in as **james** at the greeter.
3. Run `~/nullLinux/bin/null-firstrun` once, from inside that session.
4. Once it is working, `/root/nulllinux` and `/root/nulllinux-hdr-master-v4` can go.

Until step 2, the machine still runs as root and audio still reads `--`.
